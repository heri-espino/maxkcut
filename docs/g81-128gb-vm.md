# G81 on a 128 GB Linux VM — original convex SDP and GitHub checkpoints

G81 is the final and largest canonical G-set instance: **20,000 vertices,
40,000 edges**. This experiment retains the original Goemans–Williamson /
Frieze–Jerrum **full convex SDP**, solved by CVXPY/SCS on CPU. This is
**not** the separate low-rank nonconvex CUDA approach.

One 20,000 × 20,000 float64 matrix uses approximately 2.98 GiB, but
SCS cone canonicalization, duplicate arrays and PSD eigenprojections can
require **much more** memory. **128 GB RAM does not guarantee success**.
Eigenvalue decompositions may dominate computation even when RAM is free.
Use SCS tolerance 1e-3, 3000 maximum iterations, 20 rounding restarts
for each of the 3 original methods and an explicit 16-BLAS-thread limit.
SCS `optimal_inaccurate` is not an exact integer Max-Cut optimum.

## Fresh Linux VM bootstrap

Prerequisites: Git, Conda, GitHub SSH/HTTPS push credentials, at least 128 GB
RAM, adequate disk space, and a terminal kept alive or `tmux` session.

```bash
git clone https://github.com/heri-espino/maxkcut.git
cd maxkcut
eval "$(conda shell.bash hook)"
conda env create -f environment.yml
conda activate maxkcut
python -m pip install -e .
python -m pytest -q
free -h
df -h .
nproc
git branch --show-current
git remote -v
git config user.name
git config user.email
git push --dry-run origin HEAD:main
maxkcut-sdp-batch --graphs G81 --max-n 20000 --dry-run
python scripts/run_g81_vm.py --cpu-threads 16 --checkpoint-seconds 900
git push origin HEAD:main
```

If Git author identity is missing, configure YOUR real identity with
`git config user.name "YOUR GIT NAME"` and
`git config user.email "YOUR VERIFIED GIT EMAIL"`.
If GitHub authentication is missing, configure SSH or
`gh auth login` and `gh auth setup-git` before running.
The publisher never force-pushes, rebases or pulls while solving.
Remote updates from other contributors may cause a safe push rejection;
reconcile after stopping the numerical process.

If `tmux` is available, create a persistent terminal with
`tmux new -s g81-sdp` before launching, detach with Ctrl+B then D,
and reattach with `tmux attach -t g81-sdp`.

## Every 15 minutes: file/provenance checkpoints on GitHub

The VM script periodically commits/pushes the directory
[results/gset/g81-128gb-vm/](../results/gset/g81-128gb-vm/)
to GitHub `main`; this is separate from the existing Windows-machine
study under `results/gset/full-sdp/` and never overwrites it.

- `run-config.json`: precise mathematical method, seed, tolerance,
  maximum iterations, CPU thread limit and rounding budget.
- `checkpoint.json`: UTC date, graph case status, solver iteration,
  available primal/dual residuals and gap, CPU process statistics,
  available RAM, exit status, and explicit no-true-iterative-resume warning.
- `solver-output.txt`: last 10 MiB of the original verbose SCS log
  (redacted of VM home/repo paths); `batch-output.txt` for orchestration.
- `README.md`, `summary.csv`, `method-summary.csv`,
  `rounding-trials.csv`, `provenance.csv`: generated only from completed,
  independently verified source archives, with all 60 roundings when done.
- `compact-archives/`: **only after success**, the verified normalized
  signed edge graph, original bit-packed partitions for all 3 methods,
  sanitized solver/graph manifest and independent verification summary.

The complete original execution data, detailed local logs and raw SDP
cache remain under gitignored `reports/gset/g81-vm-128gb/`. Dense raw SDP
matrix caches are never Git-pushed (individual files may exceed GitHub's
ordinary file-size limits). Retain a persistent volume if you need to
preserve every local intermediate file beyond VM teardown.

Checkpoints use the **same VM process** that runs the full convex SDP;
Git commit+push occurs between monitoring intervals, not inside the
numerical solver. Ctrl+C gracefully requests interruption and attempts
one final snapshot. An OS-level VM crash may prevent the final snapshot,
but previously pushed GitHub checkpoints persist.

## Critical limitation: checkpointed logs are NOT solver-state checkpoints

The current CVXPY/SCS batch **does not save or reload intermediate
primal, dual and slack vectors**. These snapshots preserve diagnosis,
progress and final graph/partition archives, but **cannot restart G81
from iteration 500 or 1500 after an interrupted solve**. After teardown,
a new VM starts G81's numerical SDP again from scratch.

The lower-level SCS interface supports warm-starting with `x`, `y`, `s`
vectors, but implementing *genuine restartable solver-state checkpoints*
would require a different and tested backend plus possibly multi-GiB
binary state stored outside ordinary Git. No such solver checkpoint
feature is claimed.

If the same VM retains `reports/`, rerunning the same script verifies
and skips an already complete G81. A partially solved G81 restarts its
numerical iterations. Hard failures may require explicit local diagnosis
rather than automatic retry.

The final verified best rounded cut is a feasible Max-Cut lower bound,
not proof of exact integer optimality. The SDP's primal numerical
objective is not automatically a certified dual upper bound.

# Experiment001 — G77 GPU ADMM FP32: first genuine cut without CPU eig

## Research question

Can the Windows 11 RTX 4080 SUPER (16 GB VRAM, 128 GB host RAM)
produce **at least one valid signed-weight G77 Max-Cut partition** from
a **full-size convex SDP** iterate, without a second enormous CPU
eigendecomposition? This is a feasibility/rounding experiment, **not**
a claim that the SDP converges or G77 is solved optimally.

The previous G77 1-iteration preflight is archived under
`results/gset/g77-gpu-full-psd-1iter/`: full 14,000 x 14,000
GPU PSD projection succeeded in 4.33 s with 7,850,976,256 peak
PyTorch-allocated bytes, but dual residual was 59.16 and the
convergence tolerance 0.14. No cut was generated because rounding
was intentionally skipped.

## Unchanged mathematical problem

For G77's signed adjacency and Laplacian L, optimize numerically

```text
maximize <L/4, X>
subject to diag(X) = 1, X >= 0 (positive semidefinite).
```

The solver is the existing **full-matrix GPU PSD-projection ADMM**
in float32. The `gpu-admm32-adaptive` backend only changes ADMM's
numerical penalty rho, not this convex feasible region or float32
precision.

At the final GPU PSD projection, write
`Z = Q diag(max(lambda,0)) Q.T`. We already have Q and lambda
from `torch.linalg.eigh`. For independent
`g ~ N(0, I_n)`, define `s = Q @ (sqrt(max(lambda,0))*g)`,
assign `label_i = 1[s_i >= 0]`, and compute exact cut weight
using the canonical signed original graph edges. The diagonal
renormalization of Z uses positive row scales; therefore it does
not change the signs or partitions generated by this Gaussian
hyperplane procedure. The resulting distribution is the
Goemans-Williamson hyperplane distribution for the final projected
Gram, up to float32 numerical error.

This rounding uses **no CPU n x n eigendecomposition** and only
a GPU matrix-vector multiplication per trial. It is **not**
clustering; the first objective is a single actual feasible cut.
Record all 20 partitions, not just the best, for later clustering
comparison.

## Result interpretation and verification

```powershell
Import-Csv results/gset/experiment001-g77-fp32-cut/comparison.csv | Format-Table backend,solver_status,solve_seconds,continuous_primal_uncertified,cut_best,admm_converged,primal_residual,dual_residual,rho_updates -AutoSize
```

The `cases/gpu-admm32-adaptive.json` file contains the complete
numerical history, rho changes and **each** `FJ` trial's
`labels_packed_b64`. Decode a trial with
`np.unpackbits(np.frombuffer(base64.b64decode(packed),
dtype=np.uint8), count=14000, bitorder="big")` then rescore using
`maxkcut.objective.cut_weight(maxkcut.io.edge_arrays(graph), labels)`.
A score is only a feasible partition objective. At 50 iterations,
`admm_iteration_limit` is expected and is not evidence of a solved
relaxation or certified upper bound. `min_eigenvalue` is deliberately
not reported because a second CPU eigendecomposition is skipped.

If the 50-iteration run succeeds, it establishes that the procedure
can return real partitions on this hardware. A subsequent experiment
with a larger iteration budget and separate result directory is
required to assess numerical convergence. A full-rank n=14000 SDP
is computationally substantial and CUDA memory exhaustion or Windows
GPU resets remain possible.
